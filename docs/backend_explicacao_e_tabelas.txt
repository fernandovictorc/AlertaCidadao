# Relatório de Implementação do Backend e Estrutura do Banco de Dados

## 1. O que foi feito no Backend
O backend foi construído em Node.js com Express, seguindo a arquitetura em camadas MVC (Models, Controllers, Routes).
Todas as rotas e regras de negócio essenciais foram implementadas para garantir o pleno funcionamento do Alerta Cidadão:

- **Configuração do Servidor e Banco (`src/config/`)**: 
  - `db.js`: Configura a conexão (Pool) com o banco de dados PostgreSQL usando as variáveis de ambiente `.env`.
  - `initDB.js`: Script de inicialização ("Harness") que cria todas as tabelas caso não existam.

- **Middlewares (`src/middleware/`)**:
  - `authMiddleware.js`: Contém o validador de JWT para proteger rotas privadas (como perfil, criar denúncia, dar apoio).

- **Controladores (`src/controllers/`)**:
  - `userController.js`: Lida com registro (hashing de senha com bcrypt), login (geração de JWT) e edição de perfil.
  - `denunciaController.js`: Lida com criação de denúncias (anexando mídias), listagem (feed) e contagem/toggle de apoios.
  - `comentariosController.js`: Permite postar e listar comentários de uma denúncia.

- **Rotas (`src/routes/`)**:
  - Mapeamento RESTful da API (`/api/users`, `/api/denuncias`, `/api/denuncias/:id/comentarios`).

- **Integração no Frontend (`public/js/`)**:
  - `api.js`: Concentra todas as funções (usando Fetch API) que se comunicam com o backend.
  - O frontend foi preparado para utilizar essas chamadas reais ao invés de dados mockados no HTML.

## 2. Tabelas do Banco de Dados (PostgreSQL)
Para o funcionamento correto do sistema, você deve ter um banco PostgreSQL rodando. As seguintes tabelas são criadas automaticamente ao rodar o script `node src/config/initDB.js` na raiz do projeto.

### Tabela 1: `utilizadores`
Armazena os dados dos usuários da plataforma.
- `id` (SERIAL PRIMARY KEY)
- `nome` (VARCHAR(100) NOT NULL)
- `email` (VARCHAR(100) UNIQUE NOT NULL)
- `senha` (VARCHAR(255) NOT NULL) - *Armazena o hash criptografado*
- `data_nascimento` (DATE NOT NULL)
- `imagem_perfil` (TEXT) - *URL ou base64 da foto*

### Tabela 2: `denuncias`
Armazena os relatos de problemas na cidade.
- `id` (SERIAL PRIMARY KEY)
- `id_utilizador` (INTEGER REFERENCES utilizadores(id) ON DELETE CASCADE)
- `titulo` (VARCHAR(150) NOT NULL)
- `descricao` (TEXT NOT NULL)
- `morada` (VARCHAR(255) NOT NULL)
- `bairro` (VARCHAR(100) NOT NULL)
- `estado` (VARCHAR(50) DEFAULT 'Não Respondido') - *Fluxo: Não Respondido, Em Análise, Em Obra, Concluído*
- `apoios_contagem` (INTEGER DEFAULT 0)
- `data` (TIMESTAMP DEFAULT CURRENT_TIMESTAMP)
- `anonimo` (BOOLEAN DEFAULT FALSE)
- `privado` (BOOLEAN DEFAULT FALSE)
- `notificacao_pref` (VARCHAR(20) DEFAULT 'email')

### Tabela 3: `midias`
Fotos e vídeos anexados em cada denúncia.
- `id` (SERIAL PRIMARY KEY)
- `id_denuncia` (INTEGER REFERENCES denuncias(id) ON DELETE CASCADE)
- `tipo` (VARCHAR(20) NOT NULL) - *ex: 'foto' ou 'video'*
- `url_ou_base64` (TEXT NOT NULL)

### Tabela 4: `apoios`
Gerencia as "curtidas" (apoios) nas denúncias (garante que 1 usuário dê apenas 1 apoio por denúncia).
- `id` (SERIAL PRIMARY KEY)
- `id_denuncia` (INTEGER REFERENCES denuncias(id) ON DELETE CASCADE)
- `id_utilizador` (INTEGER REFERENCES utilizadores(id) ON DELETE CASCADE)
- UNIQUE constraint em (`id_denuncia`, `id_utilizador`)

### Tabela 5: `comentarios`
Fórum comunitário focado na denúncia.
- `id` (SERIAL PRIMARY KEY)
- `id_denuncia` (INTEGER REFERENCES denuncias(id) ON DELETE CASCADE)
- `id_utilizador` (INTEGER REFERENCES utilizadores(id) ON DELETE CASCADE)
- `texto` (TEXT NOT NULL)
- `data` (TIMESTAMP DEFAULT CURRENT_TIMESTAMP)

## 3. Próximos Passos
1. Certifique-se de configurar um arquivo `.env` na raiz contendo as credenciais: `DB_USER`, `DB_HOST`, `DB_NAME`, `DB_PASSWORD`, `DB_PORT`, `JWT_SECRET`.
2. Rode `node src/config/initDB.js` para gerar as tabelas no seu banco PostgreSQL.
3. Inicie a API com `npm start` (rodando na porta configurada, padrão 3000).
4. O frontend irá consumir automaticamente `http://localhost:3000/api`.
